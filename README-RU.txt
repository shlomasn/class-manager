CM ASTRA 1.3 — ПРОГРАММА УЧИТЕЛЯ ДЛЯ WINDOWS
25.11.2026

ЗАПУСК И ОБНОВЛЕНИЕ
Распакуйте весь архив на учительском Windows, закройте предыдущую версию
и замените её файлы. Запустите Start-CM.cmd. Не запускайте из ZIP.
Списки и сохранённые ключи из прошлой версии остаются в %APPDATA%\CM-Astra.
Нужен Python 3.9+ с Tcl/Tk: https://www.python.org/downloads/windows/
Первый запуск готовит отдельное окружение Paramiko 5.1.0; для этого нужен Интернет.
После подготовки программа работает в школьной сети без Интернета.

КОМПЬЮТЕРЫ И КЛАССЫ
«Добавить класс» создаёт пустой класс с произвольным названием.
Выберите класс в выпадающем списке и нажмите «Добавить ПК».
Достаточно имени, например a208-02: для DHCP выберите «По имени (DHCP / DNS)».
Можно указать полное имя a208-02.534school.spb.ru.
Если нужен фиксированный адрес, выберите «Постоянный IP» и укажите IPv4.
«Изменить ПК» редактирует текущую строку: имя, класс, режим и постоянный IP.
«Удалить отмеченные» убирает выбранные записи из программы.
«Удалить класс» убирает выбранный класс вместе с его записями компьютеров
после подтверждения. Сами компьютеры, учётные записи и домен не изменяются.
Пустые классы сохраняются; можно удалить все компьютеры и начать список заново.

Отмечайте ПК галочками в столбце «Выбор». По умолчанию выбор пустой.
При переключении класса выбор сбрасывается, чтобы не отправить команду
скрытым строкам. «Выбрать все в списке» относится только к видимому классу.
«Открыть .lst / .json» заменяет весь список; старые списки CM поддерживаются:
имя;IPv4;MAC. Старое имя 209-01 нормализуется в a209-01. MAC не используется.
В режиме DNS старый IP из .lst служит только исторической подсказкой и не
используется для подключения. Для постоянного IP выберите соответствующий
режим через «Изменить ПК». Разрешена только школьная сеть 192.168.0.0/16.
Стартовый список: 208-01..12, 209-01..12 и a210-p4, всего 25 ПК.

DHCP И DNS
Перед каждой проверкой или действием программа заново разрешает
имя.534school.spb.ru через DNS учительского Windows-ПК и использует найденный
адрес. Хранить DHCP-адрес как постоянный не требуется.
Windows должен использовать школьный DNS (в этой школе 192.168.2.11),
а DNS-запись ПК должна обновляться после смены DHCP-адреса. Программа не
меняет DHCP/DNS на сервере и не исправляет устаревшие записи автоматически.
Если имя не найдено, адресов несколько или адрес не из школьной сети,
подключение блокируется. На старый сохранённый IP программа не переключается.
Перед командой питания дополнительно сверяется реальное имя ПК.
Если DNS в школе для динамических адресов не обновляется, настройте обновление
записей на DHCP/DNS-сервере либо резервирование DHCP. При ошибке DNS можно
использовать явно указанный постоянный адрес после проверки администратором.

СОХРАНЕНИЕ ПАРОЛЯ
Нажмите «Сохранить / изменить пароль…» и один раз введите пароль локального
user на школьных ПК. Пароль сохраняется через штатный Windows Credential Manager
как Generic credential, имя записи CM-Astra/SSH/user. В исходниках, JSON,
аргументах команд, .cmd и отчётах пароля нет.
При действиях программа автоматически читает эту запись, не спрашивая пароль.
«Забыть пароль» удаляет запись. После изменения пароля на школьных ПК сохраните
новый пароль той же кнопкой. Неудачный доступ останавливает оставшуюся отправку;
автоматических повторных попыток по всем ПК нет.
Сохранённая запись доступна той же учётной записи Windows. Используйте личный
учительский профиль: пользователь этого же профиля сможет управлять ПК.
На Astra поддерживается Secret Service — подробности в разделе версии 1.2.
В plaintext-файл программа не переключается.
Если пароль не сохранён, программа запрашивает его для каждого действия.
В этой версии используется один общий пароль для user на выбранных ПК.

ДОВЕРИЕ SSH
По запросу администратора известные школьные SSH-ключи уже включены в комплект
и не вызывают первого вопроса о доверии. Каталог собран ранее в школьной сети
для 24 машин; независимая сверка каждого отпечатка не проводилась.
Ключи привязаны к имени ПК, поэтому смена DHCP-адреса не сбрасывает доверие.
Для нового неизвестного компьютера ключ подтверждается один раз в окне программы.
Далее он сохраняется за именем. a208-01 не был включён в предыдущий сбор ключей;
если он доступен по SSH, потребуется первое подтверждение.
Изменение известного ключа блокирует подключение и отправку пароля. После
переустановки или замены компьютера сначала проверьте новый ключ у администратора.
Программа не доверяет произвольному устройству только потому, что оно в классе.
Записи доверия прежней версии мигрируют с IP на имена, если в них было имя ПК.

КОМАНДЫ
«Проверить связь»: без пароля, без команд питания; показывает текущий IP и SSH.
«Выключить»: системное выключение через SSH и sudo локального user.
«Перезагрузить»: системная перезагрузка тем же способом.
«Отменить выключение»: отменяет текущее отложенное выключение ИЛИ перезагрузку,
в том числе запланированное другим администратором.
Задержки: 0, 1, 2, 5, 10, 15 и 30 минут. 0 = немедленно.
Подтверждение конкретного списка сохраняется даже при сохранённом пароле.
При 0 минут отмена уже выполненной команды невозможна; сначала сохраните работу.
Если SSH оборвётся при немедленной команде до получения статуса, результат
показывается как неподтверждённый: проверьте ПК перед повторной отправкой.
При отложенной команде успех означает принятие расписания, а не подтверждение
фактического выключения. Автоматического повтора команды питания нет.
Предупреждение systemd wall видно в открытых терминалах. Отдельный графический
агент на ПК не устанавливается; предупредите учеников о завершении работы.
«SSH недоступен» не доказывает, что питание выключено: возможна проблема сети.

ТРЕБОВАНИЯ К ASTRA
Astra Linux 1.8.4, доступный SSH и локальный user с правом sudo.
Перед sudo проверяются реальное имя компьютера и /etc/astra/build_version.
Права учеников, PAM/SSSD, домен и настройки питания ПК программа не меняет.
Новые службы, NOPASSWD, приватные SSH-ключи или агенты не устанавливаются.
Программа не включает компьютеры и не использует старые UDP-порты CM.

НАСТРОЙКИ И ПРОВЕРКА
%APPDATA%\CM-Astra\inventory.json — классы и ПК; предыдущий computers.json
подхватывается при отсутствии нового файла. reports — отчёты без пароля.
trusted-keys.json — одобренные открытые SSH-ключи, без приватных ключей.
Сохранённый пароль находится отдельно в Credential Manager Windows.
Исходные .lst не редактируются. Для удаления сохранённого пароля используйте
«Забыть пароль» либо диспетчер учётных данных Windows.

Автоматические проверки покрывают списки, классы, DNS/DHCP, смену IP с тем же
ключом, немедленные команды, хранение/чтение/удаление пароля через подставной
Windows API, отсутствие пароля в отчётах, остановку после ошибки доступа.
Реальный Windows API и графический запуск требуют проверки на Windows.
Среда разработки — macOS; запуск окна здесь ранее не удалось подтвердить.
При разработке команды питания школьным ПК не отправлялись.
Первый тест: на одном свободном ПК запланировать перезагрузку через 5 минут
и отменить её; после сохранения работы отдельно проверить 0 минут.
Тесты: .venv-win\Scripts\python.exe test_cm.py

ОБНОВЛЕНИЕ 1.2 — 25.11.2026, WINDOWS И ASTRA
Эта секция дополняет описание версии 1.1 выше.

ЗАПУСК НА ASTRA (УЧИТЕЛЬСКИЙ КОНТРОЛЛЕР)
Скопируйте и распакуйте ту же папку CM-Astra в домашний каталог учителя.
Один раз подготовьте зависимости из настроенных школьных репозиториев:
  sudo sh Install-CM-Astra.sh
Затем запускайте в обычном графическом сеансе учителя, без sudo:
  sh Start-CM.sh
Нужны Python 3.9+, Tk и Paramiko 2.12+; штатные пакеты Astra поддержаны.
Windows использует тот же интерфейс и формат списков, запуск Start-CM.cmd.
Пакеты для Linux не ставятся на Windows, и наоборот.

ХРАНЕНИЕ ПАРОЛЯ НА ASTRA
Кнопки сохранения используют Secret Service через secret-tool, libsecret-tools
и gnome-keyring. При первом сохранении может потребоваться создать или
разблокировать связку ключей отдельным системным окном. В графическом сеансе
должна работать пользовательская D-Bus-сессия. Без хранилища CM работает
с ручным вводом пароля; открытых файлов с паролями не создаёт.
На Windows остаётся Windows Credential Manager. Пароль в архив не включён.
Списки между ОС можно переносить через «Открыть .lst / .json»: поддержан и
новый inventory.json с классами, в том числе пустыми. Пароль между ОС не переносится.

ПЕРЕДАЧА ПРОГРАММ И ФАЙЛОВ
Отметьте ПК и нажмите «Передать файлы…». Выберите до 20 файлов, например .deb,
.sh или архивы. Передача выполняется по SFTP от локального user.
Перед отправкой укажите папку НА УЧЕНИЧЕСКИХ ПК, а не на компьютере учителя.
По умолчанию предлагается новая папка:
  ~/CM-Inbox/ДАТА-ВРЕМЯ-СЛУЧАЙНЫЙ_КОД
~ означает домашнюю папку user. Можно задать, например, ~/Урок или /home/user/Урок.
Одинаковый путь используется на всех выбранных ПК. Недостающие папки создаются
с правами только для user; нужны права записи у user. Символьные ссылки в пути
отклоняются. Существующие файлы не перезаписываются — выберите другую папку.
Во время работы видны текущий ПК, файл, папка, этап и процент обработки на этом ПК.
Процент включает три прохода по данным: локальный SHA-256, передачу и удалённый
SHA-256. При подключении показана анимация ожидания. Интерфейс работает через
очередь событий, сетевые операции выполняются в фоновом потоке.
Файлы не запускаются и не устанавливаются автоматически. Уже проверенные файлы
при частичной ошибке остаются; их пути и точная папка сохраняются в отчёте.

УДАЛЁННЫЕ КОМАНДЫ
Отметьте ПК, нажмите «Выполнить команду…», введите Bash-команду или несколько
строк. Без галочки sudo она выполняется от user; с галочкой — от root через sudo.
Укажите рабочую папку на ученических ПК. По умолчанию это ~ (домашняя папка
user, в том числе при sudo). Кнопка «Подставить папку последней передачи» берёт
путь последней передачи с хотя бы одним успешно проверенным файлом в этом сеансе.
Проверьте, что файлы переданы на каждый выбранный ПК: выбор компьютеров независим.
Если папки нет, команда не выполняется. Команда начинает работу в указанной папке;
сам скрипт может изменить её через cd. Перед запуском показываются ПК, папка,
права и текст команды.
Команды должны быть неинтерактивными: например apt-get с -y. SSH-терминал/PTY
не открывается, дальнейший ввод паролей/ответов внутри команды невозможен.
Безопасная первая проверка:
  hostname; uptime; id
Для установки переданного .deb подставьте папку передачи, отметьте sudo:
  apt-get -o DPkg::Lock::Timeout=180 install -y './package.deb'
Для shell-установщика подставьте папку передачи и введите:
  sh './setup.sh'
Для Python-скрипта:
  python3 './script.py'
Файлы сохраняются без права исполнения: .sh запускайте через sh или bash.
Используйте точное имя файла вместо примера; имя с пробелами заключайте в кавычки.
Это примеры для ручного ввода, программа их сама не запускает.
Таймаут 10–1800 секунд, по умолчанию 300. Вывод ограничен 64 КБ на ПК.
«Результаты» показывает коды завершения, вывод и ошибки; отчёт сохранён отдельно.
При потере связи/таймауте процесс может продолжить работу на ПК: проверьте его
перед повторной отправкой. Автоматического повтора нет. Программа не предназначена
для запуска графических окон внутри уже открытого ученического сеанса.
Не вписывайте секреты в команды: текст и вывод сохраняются в отчётах.
Общий пароль user, используемый SSH/sudo, скрывается в сохраняемых результатах.

ПОИСК ПО IP И ДОБАВЛЕНИЕ В СПИСОК
«Поиск по диапазону IP…» принимает:
  192.168.22.1-192.168.22.32
  192.168.22.0/27
  192.168.22.2,192.168.22.5,192.168.201.39
Допустимы запятые, пробелы, переносы строк; максимум 512 адресов школьной сети.
Сначала без аутентификации ищутся SSH-серверы и собираются открытые ключи.
Для ранее неизвестных ключей запрашивается согласие до отправки пароля.
Затем через закреплённый SSH-ключ проверяются реальное имя и Astra Linux 1.8.4;
обратная запись DNS/PTR не считается доказательством имени.
Неверный общий пароль останавливает остальные попытки.
В окне результатов отметьте найденные ПК и выберите класс. «Добавить выбранные»
добавит их в рабочий список; существующие записи с тем же именем обновятся и
попадут в выбранный класс. Без подтверждения список не меняется.
Дубли имени на разных IP и изменённые известные ключи блокируются.
Если прямой школьный DNS подтверждает адрес имени, новый ПК получает режим DNS.
Иначе сохраняется найденный постоянный IP: для DHCP настройте DNS и переключите
режим через «Изменить ПК». Узел без доступного SSH обнаружить этим методом нельзя.
Сканирование НЕ включает SSH на недоступных машинах.

РЕДАКТИРОВАНИЕ ГРУПП
«Добавить ПК», «Изменить ПК», «Удалить отмеченные», «Добавить класс» и
«Удалить класс» доступны в интерфейсе. «Перенести отмеченные в класс…»
массово меняет room у выбранных записей. Домен, имя и группы пользователей
на самих компьютерах при этом не меняются. Удаляются только записи CM.

SSH НА НОВОМ УЧЕНИЧЕСКОМ ПК
В обновлённом полном USB-комплекте есть 04-enable-ssh.sh.
После первых трёх этапов локально выполните:
  sudo sh 04-enable-ssh.sh
Он при необходимости устанавливает openssh-server и включает автозапуск ssh.
Пароли/ключи не копируются; недостающие ключи генерируются самим новым ПК.
Текущие sshd_config, firewall и AllowUsers не переписываются.
Если пароль user в существующей SSH-политике запрещён или порт не 22,
установщик остановится и сообщит об этом. После установки проверьте доступ
с учительского компьютера. Программа CM никогда не меняет sudoers на NOPASSWD.
Существующие подготовленные ПК тоже можно локально подготовить этим файлом.

ПРОВЕРКА ПЕРВОГО ЗАПУСКА
Новое ПО проверено автоматическими тестами с подставными SSH/SFTP и API
хранилищ. Реальные Windows/Astra GUI и связки ключей требуют пилотной проверки.
Передача, выполнение команд и изменение служб на школьных ПК при разработке
не выполнялись. На одном свободном ПК сначала проверьте hostname; uptime,
передачу небольшого файла и поиск его IP. После этого пробуйте установку ПО.
Тесты: python test_cm.py и python test_cm_extended.py (в подготовленном окружении).
