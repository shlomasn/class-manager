НОВОЕ В 2.4: ПОИСК В ЛОКАЛЬНОЙ СЕТИ БЕЗ ВВОДА ДИАПАЗОНА
«Управление и настройки → Компьютеры → Найти ПК в моей сети…».
CM читает реальные IPv4 и маски активных интерфейсов ОС учителя, без sudo и без
пробных подключений к Интернету. Windows: штатный PowerShell/NetTCPIP; Astra:
команда ip из iproute2. Выберите школьный интерфейс, учитывая возможные VPN.
Для сетей до 512 адресов проверяется вся подсеть. Более крупные сети явно
разделены на части /24; по умолчанию часть с учителем, номер можно менять.
Проверяется только выбранная часть, не вся большая сеть. IP учителя исключаются.
После нажатия «Найти компьютеры» идёт поиск SSH с текущим счётчиком проверенных IP,
затем доверие ключам, ввод логина/пароля, проверка имени/Astra и выбор добавляемых ПК.
Без SSH компьютер не обнаружится. Произвольные сети автоматически не сканируются.
Ручной «Найти ПК по IP…» сохранён. Если автоопределение недоступно, используйте его.
Новая функция Windows/Astra проверена подставными ответами ОС и реальными Tk-окнами
на macOS; на реальных Windows/Astra требуется пилот. Сеть школы не сканировалась.

НОВОЕ В 2.3: НЕЗАВИСИМЫЕ НАСТРОЙКИ СЕТИ
Необязательный домен, имена через системные настройки учителя, прямой IP и
поиск по локальным диапазонам. Новая установка пуста, без чужих ПК/SSH-ключей.
Старые inventory и системные пароли сохранены. Проверки ниже не заменяют
реальный пилот Windows/Astra в сети без DNS/AD. Поддерживаются ученики Astra 1.8.4;
управление ученическими Windows-ПК не добавлено.

НОВОЕ В 2.2: УЧЁТНЫЕ ЗАПИСИ ПК И CSV
При добавлении/редактировании ПК задаются логин SSH и пароль.
«Общий user» сохраняет прежнее поведение; «Для этого ПК» использует
индивидуальную запись Windows Credentials/Secret Service по имени ПК и логину.
Ввод нового пароля автоматически выбирает индивидуальную запись. Пустое поле
не меняет прежний пароль той же пары имя/логин. При смене имени/логина пароль
нужно задать заново либо ввести перед операцией. Старые записи не переносятся.
Есть удаление индивидуального пароля; общий пароль управляется отдельно.
Если хранилище недоступно, пароль не записывается в файл. При операции без
сохранённого пароля можно ввести его только для этой операции, без сохранения.
Для sudo используется пароль выбранного SSH-пользователя. Требуются права sudo.

«Импорт списка .csv / .lst / .json…» принимает также .csv. Формат UTF-8 (можно BOM)
или Windows-1251, разделитель точка с запятой, точный заголовок:
кабинет;компьютер;логин
208;pc-01;user
208;pc-02;admin
Шаблон: computers-example.csv. Пароли в CSV запрещены. Пустой логин = user.
Перед импортом — просмотр/подтверждение. CSV добавляет/обновляет записи по имени,
остальные ПК сохраняются. Для существующего ПК сохраняется адресация, для нового
используется DNS. Все импортированные записи используют индивидуальные пароли.
Перенос между кабинетами и обновление через поиск сохраняют учётную запись.
Старые inventory.json версии 2 без новых полей продолжают работать как общий user.
Начиная с 2.3 домен необязателен, доступны локальные IPv4 10.*, 172.16–31.*, 192.168.*.
Проверки новых хранилищ/SSH подставные; реальный пилот Windows/Astra нужен.

CM ASTRA 2.4 — ПРОГРАММА УЧИТЕЛЯ ДЛЯ WINDOWS И ASTRA
26.11.2026

ЗАПУСК И ОБНОВЛЕНИЕ
Распакуйте весь архив на учительском Windows, закройте предыдущую версию
и замените её файлы. Запустите Start-CM.cmd. Не запускайте из ZIP.
Списки и сохранённые ключи из прошлой версии остаются в %APPDATA%\CM-Astra.
Нужен Python 3.9+ с Tcl/Tk: https://www.python.org/downloads/windows/
Первый запуск готовит отдельное окружение Paramiko 5.1.0; для этого нужен Интернет.
После подготовки программа работает в школьной сети без Интернета.

НОВЫЙ ИНТЕРФЕЙС «РАБОЧАЯ ПАНЕЛЬ»
Слева — кабинеты с количеством компьютеров. Переключение кабинета очищает отметки,
но не прерывает задачи. Вверху — действия над выбранными ПК: «Раздать файлы»,
«Команда…», «Запустить файл…», меню «Питание» и «Остановить».
В «Питание» находятся выключение, перезагрузка и отмена отложенного питания;
задержка задаётся над таблицей (0 — немедленно), подтверждения сохранены.
В «Остановить» — отмена раздачи и остановка команд только на отмеченных ПК.
В строке занятого ПК доступно «Остановить»: нажатие в последнем столбце или Enter
для текущей строки действует только на этот компьютер, сохраняя остальные отметки.

Ниже таблицы — «Текущие операции» с независимым ходом выполнения. Двойной щелчок
по операции или Enter открывает обновляемое окно её состояния/результатов.
«Результаты» показывает понятный текст и исходный JSON на отдельной вкладке.
Прокрутка, текущая строка и отметки не сбрасываются при обновлении статусов.
«Выбрать свободные» отмечает только свободные ПК текущего кабинета.

«Управление и настройки» слева:
  Компьютеры → добавление, изменение текущей строки, удаление отмеченных,
  перенос в кабинет, открытие .lst/.json, поиск ПК по IP;
  Кабинеты → добавление и удаление;
  сохранение/изменение пароля и удаление сохранённого пароля.
При активных операциях изменения списка недоступны; работа со свободными ПК,
переключение кабинетов, остановка и результаты остаются доступны.

СИНХРОНИЗАЦИЯ ВРЕМЕНИ С КОМПЬЮТЕРОМ УЧИТЕЛЯ
Отметьте свободные ПК и нажмите «Синхронизировать время» рядом с проверкой связи.
Программа проверит SSH-ключи/имя/Astra, покажет выбранные компьютеры и текущие
часы учителя. Убедитесь, что дата и время учителя правильные, и подтвердите.
Требуются обычный общий пароль user и права sudo на ученических ПК.
На выбранных ПК операция выполняется параллельно, с отдельным статусом и отчётом;
остальные операции продолжаются. Занятые ПК нужно дождаться либо освободить.

Значение времени берётся заново для каждого ПК после подключения и проверки sudo,
а не из момента открытия окна. Дополнительный короткий обмен оценивает задержку
связи; половина измеренного RTT учитывается перед отправкой свежего времени.
Точность зависит от задержки и её симметрии: это ручное выравнивание по учителю,
не замена постоянной сетевой службы NTP. Если RTT превышает 5 секунд, время
не изменяется. Ожидание подтверждения ограничено общим сроком 60 секунд на задачу ПК.
После установки проверяется новое время. В «Результаты» видны было/стало,
поправка в секундах и задержка в мс. Если запрос уже отправлен, но ответ потерян,
результат отмечается как неподтверждённый: проверьте ПК перед повтором. Автоповтора нет.

Изменяется системное время через Python 3 clock_settime(CLOCK_REALTIME) от sudo.
Часовой пояс, аппаратные часы, конфигурация/состояние NTP-служб не меняются.
Время передаётся как Unix timestamp, поэтому разные часовые пояса не искажают момент.
Существующая NTP-служба может позже скорректировать время, а аппаратные часы могут
повлиять после перезагрузки. Кнопка не обещает постоянной настройки времени.
Смена часов может быть скачкообразной; состояние текущих приложений не откатывается.
Пароль передаётся только в stdin SSH-канала, не сохраняется в команде или отчёте.
При ошибке общего SSH/sudo-пароля новые попытки и ещё не отправленные запросы прекращаются.
Техническая справка Python: https://docs.python.org/3.11/library/time.html#time.clock_settime

СВЕТЛАЯ И ТЁМНАЯ ТЕМЫ
Внизу боковой панели выберите «Светлая» или «Тёмная». Тема применяется сразу,
в том числе к открытым окнам результатов, без перезапуска/остановки операций.
Выбор сохраняется в ui.json рядом с inventory.json; в этом файле только настройки
оформления, пароли по-прежнему хранятся в Windows Credentials/Secret Service.
При отсутствии или повреждении ui.json используется светлая тема.
Оформление использует стандартный Tk/ttk, без новых пакетов и загрузки шрифтов;
подбираются доступные системные шрифты Windows/Astra. Рамка окна зависит от ОС.

КОМПЬЮТЕРЫ И КЛАССЫ
«Добавить кабинет…» создаёт пустой класс с произвольным названием.
Выберите кабинет слева; в «Управление и настройки → Компьютеры» нажмите «Добавить ПК…».
Достаточно имени, например a208-02: для DHCP выберите «По имени (DHCP / DNS)».
Можно указать короткое имя pc-01 или полное pc-01.school.example.
Если нужен фиксированный адрес, выберите «Постоянный IP» и укажите IPv4.
«Изменить выбранную строку…» редактирует текущую строку: имя, класс, режим и постоянный IP.
«Удалить отмеченные ПК…» убирает выбранные записи из программы.
«Удалить текущий кабинет…» убирает выбранный класс вместе с его записями компьютеров
после подтверждения. Сами компьютеры, учётные записи и домен не изменяются.
Пустые классы сохраняются; можно удалить все компьютеры и начать список заново.

Отмечайте ПК галочками в столбце «Выбор». По умолчанию выбор пустой.
При переключении класса выбор сбрасывается, чтобы не отправить команду
скрытым строкам. «Выбрать свободные» относится только к видимому классу.
Импорт .lst/.json заменяет список, CSV добавляет/обновляет выбранные записи; старые списки CM поддерживаются:
имя;IPv4;MAC. Старое имя 209-01 нормализуется в a209-01. MAC не используется.
В режиме DNS старый IP из .lst служит только исторической подсказкой и не
используется для подключения. Для постоянного IP выберите соответствующий
режим через «Изменить выбранную строку…». Разрешены локальные IPv4 10.*, 172.16–31.* и 192.168.*.
Новая установка запускается с пустым списком. Создайте кабинет и добавьте свои ПК.

СЕТЬ БЕЗ ACTIVE DIRECTORY И ОБЯЗАТЕЛЬНОГО DNS
Active Directory не требуется. По имени используется штатное разрешение имён
ОС учителя. CM не запускает собственный mDNS/LLMNR/NetBIOS и не настраивает DNS.
Имя должно разрешаться в один локальный IPv4. Нахождение в одной сети само по
себе этого не гарантирует. Полное имя (с точками) используется как введено.
«Управление и настройки → Настройки сети…»: необязательный домен для коротких
имён. Пустое поле = ровно введённое имя; адрес DNS-сервера отдельно не нужен.
Если имена не разрешаются, выберите «Постоянный IP» или найдите ПК по диапазону.
При DHCP лучше резервирование IP, иначе после смены адреса повторите поиск.
Старый сохранённый IP при ошибке имени автоматически не используется.
До 512 адресов за один поиск, только локальные IPv4 10.*, 172.16–31.*, 192.168.*.
При поиске задаются логин и пароль; SSH-ключ и фактическое имя/Astra проверяются
перед добавлением. Неизвестные ключи требуют явного доверия.
В списках до 2.3 прежний домен сохраняется при миграции. Для другой сети очистите
его в «Настройки сети…». Изменение домена не сбрасывает доверенные SSH-ключи.

СОХРАНЕНИЕ ПАРОЛЯ
Нажмите «Сохранить / изменить пароль…» и один раз введите пароль локального
user на школьных ПК. Пароль сохраняется через штатный Windows Credential Manager
как Generic credential, имя записи CM-Astra/SSH/user. В исходниках, JSON,
аргументах команд, .cmd и отчётах пароля нет.
При действиях программа автоматически читает эту запись, не спрашивая пароль.
«Забыть сохранённый пароль» удаляет запись. После изменения пароля на школьных ПК сохраните
новый пароль той же кнопкой. Неудачный доступ останавливает оставшуюся отправку;
автоматических повторных попыток по всем ПК нет.
Сохранённая запись доступна той же учётной записи Windows. Используйте личный
учительский профиль: пользователь этого же профиля сможет управлять ПК.
На Astra поддерживается Secret Service — подробности в разделе версии 1.2.
В plaintext-файл программа не переключается.
Если пароль не сохранён, программа запрашивает его для каждого действия.
В этой версии используется один общий пароль для user на выбранных ПК.

ДОВЕРИЕ SSH
По запросу администратора известные школьные SSH-ключи уже включены в комплект
и не вызывают первого вопроса о доверии. Каталог собран ранее в школьной сети
для 24 машин; независимая сверка каждого отпечатка не проводилась.
Ключи привязаны к имени ПК, поэтому смена DHCP-адреса не сбрасывает доверие.
Для нового неизвестного компьютера ключ подтверждается один раз в окне программы.
Далее он сохраняется за именем. a208-01 не был включён в предыдущий сбор ключей;
если он доступен по SSH, потребуется первое подтверждение.
Изменение известного ключа блокирует подключение и отправку пароля. После
переустановки или замены компьютера сначала проверьте новый ключ у администратора.
Программа не доверяет произвольному устройству только потому, что оно в классе.
Записи доверия прежней версии мигрируют с IP на имена, если в них было имя ПК.

КОМАНДЫ
«Проверить связь»: без пароля, без команд питания; показывает текущий IP и SSH.
«Выключить»: системное выключение через SSH и sudo локального user.
«Перезагрузить»: системная перезагрузка тем же способом.
«Питание → Отменить запланированное выключение / перезагрузку…»: отменяет текущее отложенное выключение ИЛИ перезагрузку,
в том числе запланированное другим администратором.
Задержки: 0, 1, 2, 5, 10, 15 и 30 минут. 0 = немедленно.
Подтверждение конкретного списка сохраняется даже при сохранённом пароле.
При 0 минут отмена уже выполненной команды невозможна; сначала сохраните работу.
Если SSH оборвётся при немедленной команде до получения статуса, результат
показывается как неподтверждённый: проверьте ПК перед повторной отправкой.
При отложенной команде успех означает принятие расписания, а не подтверждение
фактического выключения. Автоматического повтора команды питания нет.
Предупреждение systemd wall видно в открытых терминалах. Отдельный графический
агент на ПК не устанавливается; предупредите учеников о завершении работы.
«SSH недоступен» не доказывает, что питание выключено: возможна проблема сети.

ТРЕБОВАНИЯ К ASTRA
Astra Linux 1.8.4, доступный SSH и локальный user с правом sudo.
Перед sudo проверяются реальное имя компьютера и /etc/astra/build_version.
Права учеников, PAM/SSSD, домен и настройки питания ПК программа не меняет.
Новые службы, NOPASSWD, приватные SSH-ключи или агенты не устанавливаются.
Программа не включает компьютеры и не использует старые UDP-порты CM.

НАСТРОЙКИ И ПРОВЕРКА
%APPDATA%\CM-Astra\inventory.json — классы и ПК; предыдущий computers.json
подхватывается при отсутствии нового файла. reports — отчёты без пароля.
trusted-keys.json — одобренные открытые SSH-ключи, без приватных ключей.
Сохранённый пароль находится отдельно в Credential Manager Windows.
Исходные .lst не редактируются. Для удаления сохранённого пароля используйте
«Забыть сохранённый пароль» либо диспетчер учётных данных Windows.

Автоматические проверки покрывают списки, классы, DNS/DHCP, смену IP с тем же
ключом, немедленные команды, хранение/чтение/удаление пароля через подставной
Windows API, отсутствие пароля в отчётах, остановку после ошибки доступа.
Реальный Windows API и графический запуск требуют проверки на Windows.
Среда разработки — macOS; запуск окна здесь ранее не удалось подтвердить.

ЗАПУСК НА ASTRA (УЧИТЕЛЬСКИЙ КОНТРОЛЛЕР)
Скопируйте и распакуйте ту же папку CM-Astra в домашний каталог учителя.
Один раз подготовьте зависимости из настроенных школьных репозиториев:
  sudo sh Install-CM-Astra.sh
Затем запускайте в обычном графическом сеансе учителя, без sudo:
  sh Start-CM.sh
Нужны Python 3.9+, Tk и Paramiko 2.12+; штатные пакеты Astra поддержаны.
Windows использует тот же интерфейс и формат списков, запуск Start-CM.cmd.
Пакеты для Linux не ставятся на Windows, и наоборот.

ХРАНЕНИЕ ПАРОЛЯ НА ASTRA
Кнопки сохранения используют Secret Service через secret-tool, libsecret-tools
и gnome-keyring. При первом сохранении может потребоваться создать или
разблокировать связку ключей отдельным системным окном. В графическом сеансе
должна работать пользовательская D-Bus-сессия. Без хранилища CM работает
с ручным вводом пароля; открытых файлов с паролями не создаёт.
На Windows остаётся Windows Credential Manager. Пароль в архив не включён.
Списки между ОС можно переносить через «Импорт списка .csv / .lst / .json…»: поддержан и
новый inventory.json с классами, в том числе пустыми. Пароль между ОС не переносится.

РАЗДАЧА ПРОГРАММ И ФАЙЛОВ
Отметьте ПК и нажмите «Раздать файлы». Выберите от 1 до 20 файлов на компьютере
учителя, затем папку НА УЧЕНИЧЕСКИХ ПК. По умолчанию:
  ~/Desktops/Desktop1/CM-Inbox
~ означает домашнюю папку user; подкаталога с датой нет. Путь можно изменить.
Раздача идёт одновременно на все выбранные ПК: каждый получает все выбранные
файлы через собственное SFTP-соединение, не ожидая завершения остальных ПК.
На одном ПК файлы обрабатываются по очереди. Кнопки «Передать файлы…» и
«Скачать файл учителя…» объединены; отдельный режим HTTP/SSH-forwarding убран.
Дополнительный сервер или разрешение TCP forwarding больше не нужны.

SHA-256 каждого учительского файла готовится один раз перед раздачей. В строке
ПК показаны текущий файл, этап и процент передачи/удалённой проверки SHA-256
по всему набору файлов на этом ПК. Нижняя полоса показывает общую обработку
ПК, включая завершившиеся с ошибкой и пропуском. Интерфейс получает события
из фоновых потоков; SSH/SFTP не выполняются в Tk-потоке.
Только подключение с общим паролем проверяется по очереди: после ошибки пароля
новые попытки прекращаются; уже начатые передачи могут завершиться. На каждом
ПК проверяются SSH-ключ, фактическое имя и Astra до изменения файлов.

Недостающие папки создаются с правами только для user; нужны права записи user.
Ссылки в пути не допускаются. Если файл существует, показываются ПК и полный
путь и задаётся вопрос «Перезаписать файл?». «Да» заменяет его только после
успешной проверки SHA-256; «Нет» сохраняет старый файл и пропускает эту копию,
продолжая остальные файлы/ПК. По умолчанию выбран ответ «Нет». Вопрос не
останавливает передачи, уже выполняющиеся на других ПК; их вывод в таблице
обновится после закрытия вопроса. Каталоги и ссылки вместо файла не заменяются.
Замена атомарная через SFTP posix-rename: при отсутствии поддержки ошибка,
старый файл не удаляется. Уже проверенные файлы при частичной ошибке остаются,
их пути сохраняются в отчёте. При таймауте проверьте ПК перед повтором;
автоматического повтора нет. Раздача ничего не запускает и не устанавливает.

ОТМЕНА РАЗДАЧИ НА ЧАСТИ ПК
Отметьте в таблице ПК, которые ещё получают файлы (их теперь можно отмечать),
и нажмите «Отменить раздачу выбранным». Команды и раздачи остальных ПК продолжаются.
Отменяется оставшаяся передача всего набора на этих ПК, без закрытия CM.
Уже проверенные файлы остаются. Текущий неполный файл не считается переданным;
после разрыва соединения временный .part может остаться. Автоповтора нет.
Сначала виден статус «Отмена раздачи…», затем результат отмены; только после
завершения потока этот ПК освобождается для новых задач. Отмена не запускает
и не удаляет переданные файлы. Строки со свободными ПК или выполняющими команду
кнопка игнорирует. «Выбрать свободные» по-прежнему выбирает свободные ПК для новых задач;
для выборочной отмены отметьте нужные получающие ПК вручную.
Отмена ожидающего ответа о перезаписи ПК прерывает ожидание. Отмена всех ПК
во время общей подготовки SHA-256 завершает раздачу без подключения к ним.

ОСТАНОВКА КОМАНДЫ НА ВЫБРАННЫХ ПК
Отметьте ПК, на которых выполняются команды, и нажмите «Остановить команды выбранным».
После предупреждения о незавершённой установке подтвердите остановку. Команды
и раздачи остальных ПК продолжатся, программа останется открытой.
Если команда ещё не отправлена, она отменяется до запуска. Ожидающую своей
очереди проверки SSH команду можно отменить, не ожидая подключения другого ПК.
Если команда уже работает, по тому же SSH-каналу отправляется запрос удалённому
управляющему процессу Python 3. Он запускает Bash в отдельной группе процессов
и посылает только этой группе SIGTERM, затем через 3 секунды SIGKILL.
Для sudo-команды управляющий процесс имеет те же права root и может завершить
её дочерние процессы. Пароль по-прежнему только в stdin, не в аргументах/файлах.
Папка user определяется до sudo. Ввод команд остаётся неинтерактивным.

При запросе виден статус «Остановка команды», затем «Команда остановлена» только
при получении подтверждения. Ожидание ответа на остановку — до 10 секунд.
При потере связи, отказе прав или отсутствии ответа показывается «Остановка
не подтверждена»: перед новой попыткой проверьте процессы на ПК. Автоповтора нет.
ПК освобождается по результату, а не сразу после нажатия кнопки. Закрытие SSH само
по себе не объявляется успешной остановкой. При обычном таймауте команды её
результат остаётся неопределённым, принудительная остановка автоматически не посылается.
Остановка не откатывает изменения: прерванная установка пакета может остаться
незавершённой. Уже запущенные службы и процессы, вышедшие из группы запуска
(например, через systemd или собственный setsid), могут продолжить работу.
Отдельные команды kill/pkill по имени процесса на ПК программа не выполняет.
Требуется Python 3 с Linux waitid/WNOWAIT; при отсутствии поддержки команда
не запускается. Управляющий процесс не создаёт файлов с паролями или скриптами.

РАБОТА С НЕСКОЛЬКИМИ ОПЕРАЦИЯМИ
Раздача и выполнение команд работают в фоне. Пока Wi-Fi ПК продолжают получать
файлы, можно переключить кабинет и отправить команду или начать другую раздачу
на свободных компьютерах. Выбор начавшейся операции очищается автоматически.
«Выбрать свободные» отмечает только свободные ПК. Занятый ПК нельзя включить
во вторую операцию: дождитесь его собственного результата. Как только ПК закончил,
он доступен для новой задачи, даже если другие ПК старой раздачи ещё работают.
Подтверждение и подготовка новой задачи кратковременно занимают общий интерфейс;
ожидание окончания передачи или команды этого не делает. Изменение списка/классов
и поиск с добавлением ПК недоступны до завершения активных операций; навигация,
выбор свободных ПК, новые раздачи, команды и просмотр результатов доступны.
У каждой операции свои параметры, прогресс и JSON-отчёт. Поздний прогресс старой
операции не заменяет результат новой на том же ПК. Успешно переданный .sh/.deb
можно выбрать для запуска сразу, не ожидая итогового отчёта всей раздачи.

ЗАКРЫТИЕ ПРОГРАММЫ
Если есть раздачи, команды, проверка связи или поиск ПК, при выходе показываются
незавершённые операции и вопрос «Закрыть программу?». По умолчанию «Нет»:
окно остаётся открытым и работа продолжается. Если задач нет, вопроса нет.
«Да» сохраняет отдельные отчёты *-interrupted-*.json, останавливает локальные
задачи и закрывает активные SSH-соединения. Ожидание ответа о перезаписи также
прерывается. Уже проверенные файлы остаются; неполные .part могут остаться.
Уже отправленная удалённая команда установки или питания может продолжить
работу после закрытия CM. Незавершённый результат отмечается как неподтверждённый;
перед повтором проверьте ПК. Закрытие CM не отменяет запланированное выключение.

ЗАПУСК ПЕРЕДАННОГО .SH / УСТАНОВКА .DEB
Отметьте ПК и нажмите «Запустить файл…». Выберите файл из списка.
Список берётся из последних 100 отчётов раздачи и старых передач/скачиваний, включая предыдущие
сеансы. Показываются имя, краткая SHA-256 и наличие на выбранных ПК. Один файл
с одинаковой SHA-256 может иметь разные папки на разных ПК — пути сохраняются
отдельно. При отсутствии записи о передаче хотя бы на одном выбранном ПК
сначала передайте файл туда или снимите выбор этого ПК.
Для .sh автоматически подставляется /bin/bash './имя.sh', для .deb —
apt-get -o DPkg::Lock::Timeout=180 install -y './имя.deb' и включается sudo.
Папка подставляется из отчёта для каждого ПК. Команду и права можно проверить
и изменить в обычном окне команды; «Продолжить…» открывает отдельное подтверждение.
Перед запуском сверяются имя ПК, Astra, SSH-ключ и SHA-256 выбранного файла.
Если файл удалён/изменён, запуск на этом ПК отменяется. Удалённый файл после
запуска не удаляется; передача и скачивание сами ничего не запускают.

УДАЛЁННЫЕ КОМАНДЫ
Отметьте ПК, нажмите «Команда…», введите Bash-команду или несколько
строк. Без галочки sudo она выполняется от user; с галочкой — от root через sudo.
Укажите рабочую папку на ученических ПК. По умолчанию это ~ (домашняя папка
user, в том числе при sudo). Кнопка «Подставить папку последней передачи» берёт
путь последней передачи с хотя бы одним успешно проверенным файлом в этом сеансе.
Проверьте, что файлы переданы на каждый выбранный ПК: выбор компьютеров независим.
Если папки нет, команда не выполняется. Команда начинает работу в указанной папке;
сам скрипт может изменить её через cd. Перед запуском показываются ПК, папка,
права и текст команды.
Команды должны быть неинтерактивными: например apt-get с -y. SSH-терминал/PTY
не открывается, дальнейший ввод паролей/ответов внутри команды невозможен.
Безопасная первая проверка:
  hostname; uptime; id
Для установки переданного .deb подставьте папку передачи, отметьте sudo:
  apt-get -o DPkg::Lock::Timeout=180 install -y './package.deb'
Для shell-установщика подставьте папку передачи и введите:
  sh './setup.sh'
Для Python-скрипта:
  python3 './script.py'
Файлы сохраняются без права исполнения: .sh запускайте через sh или bash.
Используйте точное имя файла вместо примера; имя с пробелами заключайте в кавычки.
Это примеры для ручного ввода, программа их сама не запускает.
Таймаут 10–1800 секунд, по умолчанию 300. Вывод ограничен 64 КБ на ПК.
Во время команды в строке ПК отображаются «Выполняется», прошедшее время
и последняя строка stdout/stderr (например, этап установки пакета). Даже если
команда молчит, время обновляется каждые полсекунды. Команды на выбранных ПК выполняются одновременно: у каждого отдельный поток
и собственные время/вывод/результат. Не нужно ждать завершения предыдущего ПК.
Только короткая проверка SSH с общим паролем идёт по очереди. Ошибка общего
SSH/sudo-пароля останавливает новые попытки/ещё не отправленные команды;
уже выполняющиеся команды могут завершиться. Автоматических повторов нет.
У произвольного Bash-скрипта нет общего процента готовности; показывается его
фактический текстовый вывод, без выдуманного процента. Некоторые установщики
буферизуют вывод — в этом случае до новой строки виден счётчик времени.
При завершении промежуточный статус заменяется результатом и кодом выхода.
Общий пароль скрывается и в текущем выводе, в том числе при разрыве между SSH-чтениями.
При ошибке или таймауте последний полученный вывод также остаётся в отчёте.
«Результаты» показывает коды завершения, вывод и ошибки; отчёт сохранён отдельно.
При потере связи/таймауте процесс может продолжить работу на ПК: проверьте его
перед повторной отправкой. Автоматического повтора нет. Программа не предназначена
для запуска графических окон внутри уже открытого ученического сеанса.
Не вписывайте секреты в команды: текст и вывод сохраняются в отчётах.
Общий пароль user, используемый SSH/sudo, скрывается в сохраняемых результатах.

ПОИСК ПО IP И ДОБАВЛЕНИЕ В СПИСОК
«Поиск по диапазону IP…» принимает:
  192.168.22.1-192.168.22.32
  192.168.22.0/27
  192.168.22.2,192.168.22.5,192.168.201.39
Допустимы запятые, пробелы, переносы строк; максимум 512 адресов школьной сети.
Сначала без аутентификации ищутся SSH-серверы и собираются открытые ключи.
Для ранее неизвестных ключей запрашивается согласие до отправки пароля.
Затем через закреплённый SSH-ключ проверяются реальное имя и Astra Linux 1.8.4;
обратная запись DNS/PTR не считается доказательством имени.
Неверный общий пароль останавливает остальные попытки.
В окне результатов отметьте найденные ПК и выберите класс. «Добавить выбранные»
добавит их в рабочий список; существующие записи с тем же именем обновятся и
попадут в выбранный класс. Без подтверждения список не меняется.
Дубли имени на разных IP и изменённые известные ключи блокируются.
Если прямой школьный DNS подтверждает адрес имени, новый ПК получает режим DNS.
Иначе сохраняется найденный постоянный IP: для DHCP настройте DNS и переключите
режим через «Изменить выбранную строку…». Узел без доступного SSH обнаружить этим методом нельзя.
Сканирование НЕ включает SSH на недоступных машинах.

РЕДАКТИРОВАНИЕ ГРУПП
«Добавить ПК», «Изменить выбранную строку…», «Удалить отмеченные ПК…», «Добавить кабинет…» и
«Удалить текущий кабинет…» доступны в интерфейсе. «Перенести отмеченные в кабинет…»
массово меняет room у выбранных записей. Домен, имя и группы пользователей
на самих компьютерах при этом не меняются. Удаляются только записи CM.

SSH НА НОВОМ УЧЕНИЧЕСКОМ ПК
В обновлённом полном USB-комплекте есть 04-enable-ssh.sh.
После первых трёх этапов локально выполните:
  sudo sh 04-enable-ssh.sh
Он при необходимости устанавливает openssh-server и включает автозапуск ssh.
Пароли/ключи не копируются; недостающие ключи генерируются самим новым ПК.
Текущие sshd_config, firewall и AllowUsers не переписываются.
Если пароль user в существующей SSH-политике запрещён или порт не 22,
установщик остановится и сообщит об этом. После установки проверьте доступ
с учительского компьютера. Программа CM никогда не меняет sudoers на NOPASSWD.
Существующие подготовленные ПК тоже можно локально подготовить этим файлом.

ПРОВЕРКА ПЕРВОГО ЗАПУСКА
Новое ПО проверено автоматическими тестами с подставными SSH/SFTP и API
хранилищ. Реальные Windows/Astra GUI и связки ключей требуют пилотной проверки.
Передача, выполнение команд и изменение служб на школьных ПК при разработке
не выполнялись. На одном свободном ПК сначала проверьте hostname; uptime,
передачу небольшого файла и поиск его IP. После этого пробуйте установку ПО.
Тесты: python test_cm.py и python test_cm_extended.py (в подготовленном окружении).

другого, запуск команды на освободившемся ПК и независимые отчёты операций.
